Customers represent the people or businesses you move money for — senders, recipients, merchants, or internal entities. Every organisation gets a **primary customer** at signup (representing the organisation itself). Existing routes without a customer are attributed to this primary customer.

**Required scopes:** `transfers:read` (list / get), `transfers:write` (create)

## Why customers matter

- Attach `customerId` to [payment routes](/products/payment-routes), [payment links](/products/payment-links), and [local fiat](/products/fiat-rails) orders for per-counterparty tracking
- Filter `GET /v1/transactions?customerId=...`
- Reconcile by customer name in the transactions ledger

## List customers

```bash
curl https://api.remitflex.io/v1/customers \
  -H "Authorization: Bearer $REMITFLEX_API_KEY"
```

Response:

```json
{
  "status": "success",
  "message": "Customers fetched",
  "data": {
    "customers": [
      {
        "id": "uuid",
        "name": "Acme Ltd",
        "email": "treasury@acme.io",
        "type": "business",
        "isPrimary": true,
        "createdAt": "2026-06-01T00:00:00.000Z"
      }
    ],
    "total": 1
  }
}
```

## Get a customer

Replace `{customerId}` with the RemitFlex customer UUID from list or create.

```bash
curl https://api.remitflex.io/v1/customers/{customerId} \
  -H "Authorization: Bearer $REMITFLEX_API_KEY"
```

Includes the `cngn` block when enablement has been started or completed (`enabled`, `status`, `evmWallet`, `virtualAccount`, `syncedAt`).

## Create a customer

```bash
curl -X POST https://api.remitflex.io/v1/customers \
  -H "Authorization: Bearer $REMITFLEX_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Jane Supplier",
    "email": "jane@supplier.co.ke",
    "type": "individual"
  }'
```

| Field | Rules |
|-------|-------|
| `name` | 2–120 characters; **at least first and last** (required for cNGN BVN name matching) |
| `email` | Valid email |
| `type` | `individual` or `business` (default: `individual`) |

## Dashboard

View and filter activity per customer at [dashboard.remitflex.io](https://dashboard.remitflex.io). On the customer **cNGN** tab you can **enable with BVN** to create the Smart Wallet and NGN deposit account. Completion is webhook-first (`cngn.customer.enabled`).

## Enable cNGN

Use the RemitFlex customer UUID from the list or create response as `{customerId}`. Use the **BVN holder's full legal name** (first and last) on the customer — after KYC, RemitFlex only exposes StRails profile data when names match under a strict check.

```bash
curl -X POST https://api.remitflex.io/v1/cngn/customers/{customerId}/enable \
  -H "Authorization: Bearer $REMITFLEX_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H "Content-Type: application/json" \
  -d '{"bvn":"22222222222"}'
```

See [cNGN](/products/cngn#enable-cngn) for fields, wallets, and webhooks.
